# SUTRA — Phase 6: Cohort Learning Analyst, End-to-End Hardening & Presentation Readiness

## 1. Executive Summary

Phase 6 completes the SUTRA Student Success & Intervention Orchestration Engine roadmap by introducing **Agent 7 (Cohort Learning Analyst)**, deterministic pre-agent aggregation with small-group disclosure control, a tamper-evident audit export workflow, and an institutional dashboard view (Screen E).

SUTRA now integrates seven bounded AI agents around a verifiable, append-only SQLite Support Evidence Ledger:
1. **Agent 1 — Signal Interpreter:** Explains Day-30 telemetry and LMS velocity without clinical/speculative inferences.
2. **Agent 2 — Intervention Strategist:** Selects catalog-grounded support strategies.
3. **Agent 3 — Support Plan Designer:** Proposes 1–5 milestone action steps with observable evidence triggers.
4. **Agent 4 — Evidence Challenge Agent:** Adversarially critiques support plans, flagging ambiguities and evidence gaps.
5. **Agent 5 — Stakeholder Communication Drafter:** Generates empathetic, template-grounded draft messages without numbers or probabilities.
6. **Agent 6 — Follow-up Note Structuring Agent:** Deconstructs unstructured interaction notes into distinct provenance categories.
7. **Agent 7 — Cohort Learning Analyst:** Explains precomputed aggregate statistics across cohorts with mandatory bracketed metric citations (`[M_...]`) and zero causal efficacy claims.

## 2. Agent 7: Cohort Learning Analyst Architecture

### 2.1 Core Architectural Principles
- **Precomputed, Grounded Input Only:** Under no circumstances does Agent 7 process raw student telemetry vectors, personal identifiers, demographic columns, or individual advisor notes. It receives strictly a `CohortAggregatePacket` composed of deterministic `AggregateMetricItem` objects calculated in Python/SQL before model invocation.
- **No Hallucinated Numerators or Denominators:** Agent 7 is barred from recalculating statistics, inventing percentages, or estimating longitudinal trends. Every numerical claim in its narrative must cite the source metric in brackets (e.g. `[M_CASE_COUNT_TOTAL]`).
- **Non-Causal Governance Boundary:** Educational interventions correlate with support workflows, but observational data cannot establish causal efficacy. Agent 7 is strictly prohibited from asserting that support plans or outreach *caused* course completion, grade improvement, or retention.
- **Task Execution vs. Outcome Decoupling:** Support task completion measures staff fidelity to approved plans. Student outcomes measure registrar-verified academic performance. Agent 7 explicitly highlights this operational distinction.

### 2.2 System Prompt & Prompt Construction
The system prompt (`COHORT_LEARNING_ANALYST_SYSTEM_PROMPT_V1`) enforces:
1. Pure explanatory synthesis of precomputed figures.
2. Mandatory bracketed citation syntax: `[M_METRIC_ID]`.
3. Rejection of causal phrasing ("caused", "directly improved", "guaranteed success", "proved intervention effectiveness").
4. Separation of task execution from academic outcomes.
5. Explicit articulation of data completeness gaps, grade synchronization latency, and statistical limitations.

## 3. Deterministic Pre-Agent Analytics & Privacy Disclosure Control

### 3.1 Precomputed Metric Taxonomy (`compute_cohort_aggregates`)
Prior to invoking Agent 7, SUTRA queries the local SQLite database to compute authoritative metrics across authorized cases:
- `M_CASE_COUNT_TOTAL`: Total monitored cases in active campus boundary.
- `M_STAGE_<STATUS>`: Distribution across workflow stages (`DRAFT_AWAITING_REVIEW`, `APPROVED`, `IN_PROGRESS`, `TASKS_COMPLETED`, `CLOSED`, `REJECTED`).
- `M_TIER_<TIER>`: Distribution across ML risk tiers (`HIGH`, `ELEVATED`, `MODERATE`, `LOW`).
- `M_TASKS_TOTAL` & `M_TASKS_COMPLETED`: Count of scheduled action steps and completed steps.
- `M_TASK_COMPLETION_RATE`: Ratio of completed tasks to total tasks ($0.0 - 100.0\%$).
- `M_FOLLOWUPS_TOTAL` & `M_FOLLOWUPS_STRUCTURED`: Recorded follow-up notes and Agent 6 structured notes.
- `M_OUTCOME_<STATUS>`: Student outcome status breakdown (`UNOBSERVED`, `IN_PROGRESS`, `RECORDED`).

### 3.2 Small-Group Privacy Suppression ($N < 5$)
To protect student confidentiality against re-identification in small cohorts:
- If cohort size $N < 5$, cell breakdowns (e.g. risk tiers, specific outcome counts) are flagged with `is_suppressed=True`.
- Explanatory notes inform reviewers that cell-level counts are suppressed under institutional privacy policy.
- An explicit data quality limitation warning is added to the `CohortAggregatePacket`.

## 4. Deterministic Validation Gate for Agent 7 (`validate_cohort_report`)

Before any report generated by Agent 7 is accepted or persisted, `DeterministicValidator.validate_cohort_report` executes four deterministic checks:
1. **Snapshot & Campus Alignment:** Verifies `report.snapshot_id == packet.snapshot_id` and `report.campus_id == packet.campus_id`.
2. **Metric Reference Grounding:** Every cited metric in `report.metric_references` must exist in `packet.metrics`. Ungrounded or hallucinated metric IDs trigger `ERR_UNGROUNDED_METRIC_CITATION`.
3. **Anti-Causality Heuristic:** Scans text against prohibited causal patterns (e.g., `caused retention`, `proved that intervention caused`, `directly increased grades`). Detected violations trigger `ERR_PROHIBITED_CAUSAL_CLAIM`.
4. **Individual PII Shield:** Ensures no individual record IDs, student names, or individual telemetry features leaked into the cohort narrative (`ERR_INDIVIDUAL_STUDENT_REFERENCE`).

## 5. Support Evidence Ledger Verification & Canonical Export

### 5.1 Append-Only Hash Pointer Chain
Every state change across cases and cohort reporting appends an audit event to `audit_ledger`:
- Formula: $\text{SHA-256}(\text{prev\_entry\_hash} \parallel \text{event\_type} \parallel \text{case\_id} \parallel \text{actor\_id} \parallel \text{timestamp} \parallel \text{payload})$.
- The first event links backward to `GENESIS`.
- SQLite database-level triggers (`prevent_audit_ledger_update`, `prevent_audit_ledger_delete`) prevent in-process tampering.

### 5.2 Canonical Ledger Export (`/api/v1/audit/export`)
The export endpoint verifies the entire cryptographic chain using `verify_audit_chain()` and returns an `AuditExportPackage`:
- `export_schema_version`: `"3.0"`
- `exported_at`: ISO-8601 UTC timestamp
- `exported_by`: Authenticated actor ID
- `campus_filter`: Campus scope
- `total_events`: Count of exported events
- `is_chain_valid`: Boolean indicating mathematical continuity from `GENESIS`
- `chain_verification_message`: Detailed verification report
- `events`: Ordered list of `AuditExportEventItem` objects containing full backward pointers and canonical payloads.

If any database record has been modified out-of-band (e.g., direct SQLite file tampering), the verification algorithm detects the discrepancy and pinpoints the exact sequence ID (`corrupted_seq_id`).

## 6. Frontend: Screen E (Cohort Analytics & Ledger Export)

Screen E provides an institutional dashboard for educational leaders and auditors:
- **Campus Scope Switcher:** Allows toggling between `CAMPUS-MAIN`, `CAMPUS-REMOTE`, and `CAMPUS-SYSTEM`.
- **Precomputed Metric Cards Grid:** Displays authoritative KPI cards with hover states, modern typography, and small-group suppression badges.
- **Operational Decoupling Alert:** Reinforces that task execution does not equal student academic success.
- **Agent 7 Report Viewer:** Renders executive summary narratives, provably cited patterns, grounding citation chips, missing evidence lists, and institutional inquiry questions.
- **Verifiable Ledger Export Card:** Displays audit integrity badges (`SHA-256 CHAIN VALID` or `TAMPER DETECTED`), audit event tables, and a one-click button to download the signed `.json` export package.
